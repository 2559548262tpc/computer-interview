# 面试提问官 · interview-questioner

> 把 14 份真实互联网大厂面试录音，沉淀成一套「会追问、会给台阶、会打假」的面试提问系统。

这是一个 WorkBuddy Skill。输入 **公司 × 岗位 × 轮次 × 实习/秋招**，输出风格一致的面试题脚本——每道题都带**考察重点、引导性提问、追问链、参考答案框架**；也可以直接切到「对练模式」，让 AI 扮演面试官逐题面你。

---

## 为什么做这个

市面上的面试题大多是「题库」：只有问题，没有**怎么问、怎么追、什么时候给台阶、什么时候往死里逼**。

这个 Skill 的原材料是 14 份真实面试录音（百度、字节、蚂蚁、高德、小米），从中提炼的不是答案，而是**面试官的提问行为**：

- 他怎么用一句复述把你架住：「相当于你把 8080 端口放开给其他人用了是吗？」
- 他怎么在否定你之后又给半颗糖：「思路是好的，但是……」
- 他怎么用「最核心的那一个是什么」把背答案的人打回原形；
- 他怎么在该沉默的时候沉默 40 秒，逼你自己往下想。

这些东西，题库给不了。

## 能力

| 能力 | 说明 |
|---|---|
| **按公司出题** | 百度 / 蚂蚁 / 高德 / 字节 / 小米，各自的关注点与施压方式不同 |
| **按轮次出题** | 一面（密度与诚实）/ 二面（深度与边界）/ 三面（判断与可塑性），不是简单加深 |
| **按批次出题** | 实习 vs 秋招，两套强度；秋招为「加码推演」，可持续用真实秋招录音校正 |
| **按岗位出题** | 后端 / 全栈 / Agent / 大模型应用，考察权重不同 |
| **按侧重点出题** | 场景题、基础八股、项目深挖、算法、AI-Agent 专项 |
| **对练模式** | AI 直接扮演面试官，实时追问，结束后按五维打分 |
| **风格一致** | 口语化、复述确认、反向镜射、硬纠偏、换视角重问、抓矛盾、元反馈 |

## 快速开始

### 安装

把整个 `interview-questioner/` 目录放到以下任一位置：

```bash
# 项目级（仅当前工作区可用）
<your-project>/.workbuddy/skills/interview-questioner/

# 用户级（所有工作区可用）
~/.workbuddy/skills/interview-questioner/
```

### 调用

直接用自然语言描述需求即可，例如：

```
用这个 skill 模拟百度 AI 全栈秋招一面，我简历是 Java 后端 + Spring AI Agent
按蚂蚁风格出 Agent 二面的题，重点场景题
对练模式，你当面试官面我，最后打分
帮我分析一下字节和百度的面试风格有什么不同
```

### 示例输出（节选）

```
### Q3｜项目·痕迹型：拼团交易平台的部署
**面试官（口语原话风）**："你这个项目是本地做的，还是放到服务器上部署过？"
**考察重点**：项目真实性 / 工程闭环（痕迹型问题，背不出来）
**引导性提问**：答"部署过"→追配置与端口；答"没部署"→"那你怎么验证接口能用？"
**追问链**：部署 → 环境 → 端口 → docker 分组 → 压测 → "apifox 能真模拟并发吗" → 排障 → 日志落盘 → 磁盘满
**参考答案框架**：2C4G 云服务器 / 中间件与服务分网络 / 端口 + 防火墙 / 压测工具的局限 / 日志落盘 + 清理 + traceId
**危险信号**：只会说"用了 docker"，说不出端口、网络、日志落盘
```

## 核心设计

### 1. 四维考察模型

所有问题都落在这四个维度上，排结构时先分配权重，再出题：

| 维度 | 测什么 | 典型判据 |
|---|---|---|
| **A. 项目真实性** | 是不是你亲手做的 | 说不出端口、容器网络、日志落盘 |
| **B. 基础体系** | 知识有没有硬伤 | 定义背得出，一追"什么情况不成立"就崩 |
| **C. 场景/系统设计** | 能否把模糊需求推演成方案 | 只会罗列"加 Redis""用 MQ"，说不出副作用 |
| **D. AI/Agent 工程** | 是否真在工程里跑过 | 评估靠"人工看"、样本只有 3 个 |

一条主线：面试官最终在回答 **"你简历上的东西，是你自己的吗？"**

### 2. 轮次差异

| 轮次 | 本质 | 考什么 |
|---|---|---|
| **一面** | 密度与诚实 | 问得多、切得快，看你哪里露底；运维痕迹 + 基础广度 + 算法 |
| **二面** | 深度与边界 | 问得少、钻得深，画你的能力雷达；逼量化与归因 |
| **三面/主管** | 判断与可塑性 | 不考知识，考需求澄清、设计品味、反思、稳定性 |

### 3. 公司差异（一句话画像）

| 公司 | 画像 | 覆盖轮次 |
|---|---|---|
| **百度** | 一面运维痕迹 / 二面 AI 评估 / 三面需求澄清+接口设计 | 一面 · 二面 · 三面 |
| **字节** | 工程现实主义 + 逻辑驳斥；八股少而深，算法硬门槛 | 一面 · 三面 |
| **蚂蚁** | 零八股零算法，一道 Agent 工程题打穿，逼样本量 | 一面 · 二面 |
| **高德** | 可观测性 + 故障归因 + 代码 Review，重落地 | 二面 |
| **小米** | 技术一面（RAG+AI coding+Java 八股）/ 主管面（"最核心是什么"） | 一面 · 二面 |

### 4. 实习 vs 秋招

现有 14 份录音全部是**实习面试**。秋招版本按 7 条规则**加码推演**：

> 减台阶 · 加下钻 · 加量化 · 加算法 · 加设计 · 加 STAR · 加稳定性

秋招题会显式标注 `[秋招加码]`，避免把"推演"当成"实证"。

### 5. 提问风格

六种核心手法，全部来自录音原话：

1. **复述确认** —— 把答案折叠成一句让他确认
2. **反向镜射** —— 不评价，只陈述事实
3. **硬纠偏** —— "不是我想了解的是这个点"
4. **换视角重问** —— "交付给业务方，你以什么维度评判？"
5. **抓矛盾** —— "那你刚才又说一两千行我审核不了"
6. **元反馈** —— "你的核心观点是什么？感觉有点漂移了"

并强制：**否定后给半肯定、该沉默就沉默、收尾不评价不承诺**。

## 迭代

1. 新录音转写成 md（含时间戳 + 说话人）。
2. 按 `references/transcript-index.md` 的结构拆解：基本信息 / 面试结构 / 问题清单 / 追问链 / 风格画像 / 考察重点 / 引导话术。
3. 更新对应 `companies/*.md`；若是秋招样本，回填 `internship-vs-autumn.md` 并把"推演"改为"实证"。
4. 在新公司/新岗位出现时新增文件，并在索引表登记。

## 隐私与边界

- 本仓库**只包含 Skill 本体**，**不包含**任何录音文件或面试转写原文。
- `transcript-index.md` 仅记录"录音 → 公司/轮次/看点"的索引，不收录候选人隐私。
- 参考答案给的是**要点框架与判断标准**，不提供"背了就能过"的全文答案。
