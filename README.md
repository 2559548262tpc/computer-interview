# interview-questioner

> 基于真实面试录音整理的面试提问 Skill。给定公司、岗位、轮次和招聘批次，生成一套「像真人问的」面试题。

面试题不缺题库，缺的是**怎么问、怎么追、什么时候给台阶**。这个 Skill 从 14 份大厂面试录音（百度、字节、蚂蚁、高德、小米）里提炼的是面试官的**提问行为**，而不是标准答案。

支持两种模式：

- **脚本模式**：一次输出整套面试题，每题包含「考察重点 / 引导性提问 / 追问链 / 参考答案框架」。
- **对练模式**：AI 扮演面试官逐题发问，按你的回答实时追问，结束后按维度打分。

## 安装

把 `interview-questioner/` 放到以下任一位置：

```bash
# 项目级：只在当前工作区生效
<your-project>/.workbuddy/skills/interview-questioner/

# 用户级：所有工作区生效
~/.workbuddy/skills/interview-questioner/
```

## 使用

用自然语言描述即可：

```
用这个 skill 模拟百度 AI 全栈秋招一面，我简历是 Java 后端 + RAG
按蚂蚁风格出 Agent 二面的题，重点场景题
对练模式，你当面试官面我，最后打分
对比一下字节和百度的面试风格
```

输出示例（节选）：

```
### Q3｜项目·痕迹型：拼团交易平台的部署
面试官："你这个项目是本地做的，还是放到服务器上部署过？"
考察重点：项目真实性 / 工程闭环（痕迹型问题，背不出来）
引导性提问：答"部署过"→追配置与端口；答"没部署"→"那你怎么验证接口能用？"
追问链：部署 → 环境 → 端口 → docker 分组 → 压测 → "apifox 能真模拟并发吗" → 排障 → 日志落盘 → 磁盘满
参考答案框架：云服务器配置 / 中间件与服务分网络 / 端口与防火墙 / 压测工具局限 / 日志落盘与清理
危险信号：只会说"用了 docker"，说不出端口、网络、日志落盘
```

## 设计要点

**四维考察模型**：所有问题都落在「项目真实性 / 基础体系 / 场景设计 / AI 工程」四个维度。排结构时先分配权重，再出题。

**轮次差异**：
- 一面 = 密度与诚实，问得多、切得快，看哪里露底；
- 二面 = 深度与边界，问得少、钻得深，逼量化与归因；
- 三面 = 判断与可塑性，考需求澄清、设计品味、反思和稳定性。

**公司差异**：

| 公司 | 关注点 |
|---|---|
| 百度 | 运维痕迹、Agent 评估、接口设计 |
| 字节 | 工程落地、逻辑自洽、算法硬门槛 |
| 蚂蚁 | 状态与上下文、评估方法论、样本量 |
| 高德 | 可观测性、故障归因、代码 Review |
| 小米 | RAG 全链路、AI coding 真实度、主管追问收敛 |

**实习 vs 秋招**：现有样本均为实习面试。秋招版本按「减台阶、加下钻、加量化、加算法、加设计、加 STAR、加稳定性」七条规则加码，并显式标注 `[秋招加码]`，避免把推演当成实证。

## 说明

- 本仓库只包含 Skill 本体，不包含任何录音文件或面试转写原文。
- 结论来自有限样本的场次画像，不代表公司官方流程；标注"推断"处请以实际面试为准。
- 参考答案提供要点框架与判断标准，不提供"背了就能过"的全文答案。

## 迭代

1. 新录音转写为带时间戳和说话人的 Markdown；
2. 按 `references/transcript-index.md` 拆解：基本信息、面试结构、问题清单、追问链、风格画像、考察重点、引导话术；
3. 更新对应 `companies/*.md`；若是秋招样本，回填 `internship-vs-autumn.md` 并把推演改为实证；
4. 新公司或新岗位出现时新增文件并登记索引。
