# 百度（AI 全栈 / AI 应用实习）

> 样本：4 份录音（同一候选人严明涛，Java 后端 + 大模型应用，百度智能办公平台部 AI 全栈实习，已 OC）。覆盖一面、二面、三面完整三轮，是本项目**最完整的三轮样本**。

## 一句话画像

**三轮问的是同一件事的三个切面——"你简历上的这些东西，是你自己的吗？"**
一面用**运维痕迹**验，二面用**知识边界**验，三面用**设计推演**验。

## 风格特征

- **口语化极高**：几乎每句带"呃/嗯/就是/那那"，常半句+自我修补，会自己换词迁就候选人（"打点"→"日志"）。
- **先问业务价值，再问实现**：项目题第一问永远是"它解决什么业务问题"。
- **复述确认**：把答案折叠成一句让候选人确认（"相当于你把 8080 端口放开给其他人用了是吗？"）。
- **反向镜射**：不批评，只陈述事实（"apifox 其实并不能真正模拟并发场景"），逼候选人自己降调。
- **反驳后给半肯定**（二面/三面）："思路是好的，但是……""这个思路是可行的"。
- **三面苏格拉底式**：不给答案，只描述症状（"层级特别深""参数有点多"），让你自己改。

## 三轮重点

### 一面（偏前端 / 直接用人方）
- **零八股、零 AI 专项**（哪怕简历主推 Agent 也不问）。
- 单项目深挖 18 分钟：业务→有没有前端→怎么测→部署没→环境→**端口→docker 分组→压测→排障→日志→落盘→磁盘满**。
- 算法 2 道 easy（爬楼梯、跳跃游戏）+ **要求写测试用例**（考自测习惯）。
- **零提示**，但听不清时降维重述。
- 反问信息给得实：业务四条线、三轮、2–3 天反馈。

### 二面（后端）
- **AI 专项占比最高（约 50%）**：RAG 切分/BM25/PGVector → Agent 三种执行策略（step/ReAct/loop）→ **Agent 评估体系**（全场压力最大）→ Harness/SubAgent。
- **八股成体系**：MQ 一致性/不丢/RabbitMQ vs Kafka、登录/OAuth2.0、HTTP/HTTPS/证书、SSE vs WebSocket。
- 算法"预告 1–2 道但实际 0 道"（时间被 AI 专项吃掉）。
- **给半答案**："肯定是实现了一个打字的效果吧"；递台阶用候选人的词（"用你刚提到的会话 ID"）。
- 压力来自**同一问题换视角重问 3 次**（"怎么评判 Agent 好坏"），不接受"依赖人工/看需求"。

### 三面（主管 / 组长）
- **零八股零算法**，但有"编码/设计环节"（手写 JSON），**明确允许用 AI 工具**。
- **反思题**："如果让你重新做，你会优化什么"（给候选人 6 分钟）。
- **开放设计题**：假设做个类似百度搜索的产品 → 需求澄清 → 传统搜索方案 → **手写接口 JSON** → 加高亮 → **高亮数据结构改 4 轮**（层级深→拍平→类型→扩展翻倍）。
- **苏格拉底式**：只给症状不给方案，改对了给正反馈（"现在比刚刚好对吧"）。
- **收尾是 9 分钟职业长谈**：技术会不会贬值、要补什么栈、语言不重要（"我们基本不怎么招 Java"）。

## 高频题（原话样本）

- "你这个项目是本地做的，还是放到服务器上部署过？"
- "你部署这些，关于环境问题你是怎么解决的？"
- "你一般监听的是服务器的哪一个端口？"
- "你 docker 一个 docker 就有一个服务吗？"
- "你是怎么测试后端服务并发场景的稳定性？"
- "服务出现问题了，你要怎么排查？"
- "你不是用 docker 部署吗？日志文件的持久化存储怎么做的？"
- "日志文件太多，是不是就把虚拟机占满了？"
- "RAG 的文本切分和入库怎么做的？"
- "讲一下 BM25 的原理吧，大概是个什么东西？"
- "你怎么评判 Agent 输出的结果是好的还是不好的？"（问 3 次）
- "假设实现一个类似百度搜索的产品，你会关注哪些点？"
- "你要告诉前端哪个字高亮，这个数据格式你会怎么定义？"
- "如果让你重新做，你觉得有什么可以优化或改造的点？"

## 评分重点

- 一面：项目真实性（痕迹型问题答不答得出）、工程闭环（测试/部署/压测/排障/可观测）、自测习惯、诚实度。
- 二面：知识边界诚实度、AI 工程评估思维（能否给出可量化维度）、后端基本功不虚、全栈协作意识。
- 三面：需求澄清、接口设计品味、被否定后的迭代能力、反思深度、技术视野与可塑性。

## 危险信号

- 一面：只会说"用了 docker/Redis"，说不出端口、网络分组、日志落盘；压测数据明显外推（"至少 5000 QPS"）。
- 二面：把"框架名"当答案；评估只会说"人工看"；八股一追就崩。
- 三面：面对模糊需求直接要"标准答案"；被指出问题后只会附和不会改；把个人项目包装成"上线项目"。

## 话术速取

- 降维重述："一个 docker 就是一个服务一个中间件嘛。"
- 复述确认："相当于你把 8080 端口放开给其他人用了是吗？"
- 反向镜射："apifox 其实并不能真正模拟并发场景。"
- 递台阶："用你刚提到的会话 ID，前端去找回原来那个。"
- 给半答案："肯定是实现了一个打字的效果吧。"
- 收题指路："这个后面优化，你把这个问题丢给 AI，让它给你点评一下。"
