# 问题库（按类别 · 含原话与追问方向）

> 用法：先按 `rounds.md` 定好各环节时长，再从本库取题。**每题后面标了"追问"和"引导"，直接拼进输出模板。** 原话可改写，但保留口语特征。

## 1. 开场 / 自我介绍 / 流程

| 原话 | 说明 |
|---|---|
| "先请你做一个自我介绍吧。" | 最简开场 |
| "你先做个自我介绍，重点讲一下你做过什么项目、解决了什么问题、中间有没有遇到什么比较困难的。" | 小米式结构化提纲（埋"困难"钩子） |
| "这边是百度的一个 AI 实习生的机会，本次面试会问一些技术问题，可能有个代码考核的环节。" | 百度式流程预告 |
| "咱们这轮面试跟之前差不多，大概还是两部分：基础 + 一道编程题。" | 字节式流程声明 |
| "我看咱们之前问了很多，你选一个最能体现你工程能力的项目展开聊。" | 三面无自我介绍，给选题权 |

**追问**：学习路径（什么时候开始学、平时怎么学）、为什么选这个方向。

## 2. 项目深挖

### 2.1 真实性 / 痕迹型（最抗包装）
| 原话 | 追问方向 |
|---|---|
| "你这项目是本地做的，还是放到服务器上部署过？" | 配置→环境→端口→容器网络→压测→排障→日志→落盘→磁盘满 |
| "你 docker 一个 docker 就有一个服务吗？" | 网络分组、compose、数据卷 |
| "服务出问题了你怎么排查？" | 日志/traceId/链路/上下游 |
| "你日志文件的持久化存储怎么做的？" | 容器日志、磁盘满、清理策略 |
| "这块哪部分是你的？端到端都你负责吗？" | 分工、协作、独立贡献 |
| "有前端吗？前后端都是你自己做的还是和同学一起？" | 独立性、AI 生成占比 |

### 2.2 业务价值 / 指标
| 原话 | 追问方向 |
|---|---|
| "它主要是解决什么业务问题的？" | 用户、场景、价值 |
| "你这个项目达成的效果指标是什么？" | 量化口径、基线、提升 |
| "优化之前什么样子，优化之后什么样子？" | 数字、归因 |
| "指标提升的核心是什么？哪些优化带来的？为什么？" | 拆解到具体手段 |

### 2.3 反思 / ownership
| 原话 | 追问方向 |
|---|---|
| "如果让你重新做，你会优化或改造哪些点？" | 反思深度、真实工程判断 |
| "这个项目最核心的是什么？只能选一个。" | 收敛能力（抗 AI 提示） |
| "中间有几次人工审核？谁保证？" | 流程闭环、责任边界 |
| "失败了谁兜底？判错了怎么处理？" | 异常路径 |

## 3. 基础八股（按主题，均可下钻）

**Java**：HashMap 底层→为什么红黑树→并发问题→ConcurrentHashMap 为什么安全；线程池参数与提交流程；JVM/GC（按岗位选）。
**MySQL**：MVCC 版本链→默认隔离级别→幻读与 Next-Key Lock→redo/binlog 两阶段提交与崩溃恢复；索引扫描 vs 全表→回表→覆盖索引→优化器怎么估选择率。
**Redis**：数据结构、SDS 的 len、单线程模型、持久化、缓存一致性、分布式锁/看门狗。
**网络**：TCP 三次握手/四次挥手→为什么挥手多一次→反事实"两次握手最坏情况"；HTTP/HTTPS→证书；HTTP 版本差异。
**安全/协议**：OAuth2.0 流程/token 有效期/scope/最小权限；SSE vs WebSocket→为什么 LLM 场景用 SSE。
**MQ**：如何保证不丢（生产确认+持久化+手动 ack）、最终一致性、RabbitMQ vs Kafka 选型。

**追问模板**：是什么 → 为什么 → 什么情况不成立 → 引擎/协议内部怎么决定。

## 4. 场景设计

| 场景 | 原话 | 追问方向 |
|---|---|---|
| 幂等下单 | "设计一个可重复写入、最终只有一条的接口，网络不可控。" | key 怎么设计→两次请求为何不同→并发→事务超时→加 Redis 的副作用 |
| 跨天长任务 | "设计一个跨天的长任务，可靠性和宕机恢复怎么保证？用户怎么感知进度？" | checkpoint 粒度/内容→调度→恢复→进度 |
| 流式续传 | "用户刷新页面，但吐字还在继续，刷完还要接上，前后端怎么实现？" | 会话 ID→后端怎么找回→连接与生成解耦→Last-Event-ID |
| 检索 | "用户要亲子房、带游泳池，这种非结构化属性怎么检索？" | 结构化字段精确 + 描述性字段向量、rerank |
| 高亮 | "告诉前端哪个字高亮，数据格式怎么定义？" | 位置区间 vs 标记文本→层级→扩展翻倍 |
| 需求澄清 | "假设做个类似百度搜索的产品，你会关注哪些点？" | 用户/边界/MVP/技术方案→传统搜索→接口 |

**引导**：给模糊需求→候选人跑偏就用"诶那假设它是传统搜索"拉回；卡住就"先不提用户/先写个 JSON/你随便写写试试"。

## 5. 系统设计 / 接口设计

- "写一个搜索接口的返回结构，字段怎么定义？"（code/status/data/items/pagination）
- "加一个高亮功能，怎么把'哪个字亮'传给前端？"（迭代 4 轮：嵌套→拍平→类型→扩展性）
- "分页怎么做？深分页怎么优化？"
- "这个类的职责边界怎么划？从 design 角度看该怎么改？"

## 6. 算法（按公司调难度）

- 字节一面：爬楼梯、跳跃游戏（easy/medium，**不给 IO、自己写 case**）
- 字节三面：货币兑换（图+BFS，**写后逐行验证**：注释某行/调换两行）
- 蚂蚁/高德：**不出算法**（改看代码 Review）
- 小米一面：合并两个有序数组（**口述思路**）
- 百度一面：爬楼梯/跳跃游戏 + **要求写测试用例**

**追问模板**：思路→时间复杂度→有没有别的方法→边界 case→（写完后）改一行会怎样。

## 7. AI / Agent 专项（大模型应用岗必考）

### 7.1 状态 / 上下文 / 记忆
- "AI 应用在线上运行时的状态机怎么管理？"（区分会话上下文/业务实时状态/长期记忆）
- "跨会话怎么办？几天甚至几个月呢？"
- "上下文怎么管理？怎么实现？"（token 计数、超阈值压缩、保留最近 N 条）
- "压缩之后怎么评估有没有丢关键信息？样本多大？"

### 7.2 评估（最高频、最区分度）
- "怎么评判 Agent 输出的结果是好的还是不好的？"（换 3 种视角重问）
- "交付给业务方，你用哪些维度证明它准确/完整？"
- "指标是什么、分子分母、样本多大、合格线怎么定？"
- 参考框架：功能层（完整性/调用链完整/时效性/准确度召回）+ 业务层（领域标准案例）

### 7.3 编排 / 容错
- "Agent 三种执行策略（step/ReAct/loop）区别？"
- "多 Agent 怎么编排？子 Agent 上下文隔离？修复循环上限？"
- "工具调用失败怎么处理？代码层还是 Agent 层？重试后 context 污染怎么办？"
- "流式返回中途失败，怎么处理给模型的输入？"

### 7.4 概念
- "MCP 解决了什么问题？和 function calling/HTTP 工具比优势在哪？"
- "skill 的本质？渐进式披露？"
- "harness 怎么理解？它出现之前这件事怎么做？"
- "sub-agent 存在的意义？"

### 7.5 可观测性（高德最爱）
- "你监控哪些指标？"（可用性/体验/质量/成本/链路）
- "产生幻觉的工具调用，你从什么地方找？"（工具选错→参数→上下文→工具定义过近→校验 Agent→模型）

## 8. 行为 / 软技能

- "你是什么时候开始学编程的？平时怎么学？"（学习路径）
- "你的自驱力来自什么？"（换壳三次：价值观/怎么评价自己）
- "为什么离开上一段实习？"
- "能实习多久？最快什么时候到岗？接不接受某城市？"
- "职业规划？怎么看技术会不会贬值？"
- "和队友有过冲突吗？怎么解决？"（秋招补）
- "最有成就感/最失败的一件事？"（秋招补，STAR）

## 9. 反问（收尾）

- "我看时间差不多了，你有什么问题问我吗？"
- 各公司信息量：蚂蚁二面会给业务/技术栈/培养机制；字节一面几乎不给；小米二面主动卖"可转秋招 offer"。
- 候选人常问：几点轮、反馈时间、团队业务、技术栈、转正/培养。
