# 实习面试 vs 秋招面试

> 现有 14 份录音**全部是实习面试**（含个别校招/日常实习，未明说）。本文件做两件事：① 说清实习面与秋招面的本质差异；② 给出"把实习录音升级成秋招风格"的可执行规则。**秋招部分目前是基于实习样本的推演，后续上传秋招录音后需用实证校正。**

## 一、本质差异

| 维度 | 实习面试（现有录音） | 秋招面试（推演，待实证） |
|---|---|---|
| **核心问题** | "你能不能来干活、学得快、待得住" | "你值不值得给一个正式 HC" |
| **项目要求** | demo 级可接受，允许"课程/比赛/仿写" | 要求真实上线/有量化收益；对"包装项目"零容忍 |
| **基础要求** | 广度扫射，能答定义即可 | 体系完整、能下钻到原理/引擎内部；八股成体系覆盖 OS/网络/DB/语言/并发 |
| **算法** | 常 1–2 道 easy/medium，允许提示 | 硬门槛，medium–hard，要求最优解 + 复杂度 + 边界 case，甚至逐行验证 |
| **场景/设计** | 有，但面试官会给台阶、代答 | 更开放、约束更少、追问更深，要求主动列约束与权衡 |
| **AI/Agent** | 问"用没用过/怎么搭的" | 问"线上怎么坏、怎么评估、怎么控成本、怎么做回归" |
| **追问强度** | 中等，答不上常换题 | 高，同一问题换 3–4 种问法逼到底，抓前后矛盾 |
| **行为/软技能** | 问学习路径、自驱力、能实习多久 | 加 STAR（冲突/失败/最有成就感/职业规划）、稳定性、地域 |
| **收尾** | 常给"3 个工作日反馈" | 多为"等通知"，流程更长（HR 面/加面） |
| **通过率** | 相对高 | 显著低，横向对比同一批候选人 |

## 二、把"实习录音"升级成"秋招风格"的 7 条规则

生成秋招题时，在实习模板基础上做如下**加码**（不要改口吻，只改强度与覆盖面）：

1. **减台阶**：删掉"没有标准答案""你随便写写""我直观感觉"这类让步；把"给半答案"改成"只描述症状"。
2. **加下钻层数**：基础题从"是什么→为什么"扩到"是什么→为什么→什么情况不成立→引擎/协议内部怎么决定"。例：三次握手 → 为什么两次不行 → 反事实推演最坏情况 → 丢包+乱序组合。
3. **加量化与归因**：项目题强制追问"指标多少、分子分母、优化前后、为什么是 0.9、样本多大"。
4. **加算法权重**：一面算法占比提到 40%+，并要求"先讲思路+数据结构→再写→自己设计边界 case→改一行验证"。
5. **加系统设计**：至少 1 道完整设计题（幂等/长任务/检索/Agent 编排），追问"副作用、次生成本、扩展性"。
6. **加行为 STAR**：补 2–3 道（最有挑战的项目/和队友冲突/失败复盘/职业规划/为什么这家）。
7. **加稳定性与匹配**：城市、到岗、能待多久、是否有其他 offer、为什么选我们。

## 三、秋招版"加码"示例（同一道题的实习 vs 秋招）

**实习版（百度一面原话）**
> "你这个项目是本地做的，还是放到服务器上部署过？"

**秋招版（加码）**
> "你这个项目部署过吗？——什么配置的机器？为什么选这个配置？上过线吗？QPS 峰值多少？压测怎么做的、工具能真实模拟并发吗？如果流量翻十倍，你先动哪里？为什么不是另一个？"

**实习版（蚂蚁二面原话）**
> "你们做上下文压缩，怎么评估压缩之后会不会丢关键信息？"

**秋招版（加码）**
> "压缩效果怎么评估？指标是什么、怎么算的？样本多大、怎么采样？人工筛查的一致性怎么保证？如果换一版压缩模板，你怎么证明没退化？线上出现'关键信息丢失'的 bad case，你怎么定位是切分、压缩还是召回的问题？"

## 四、秋招模拟的输出标注

生成秋招题时，在脚本开头标注：
```
> 批次：秋招（基于实习录音的加码推演，非秋招实证）
> 加码项：减台阶 / 加下钻 / 加量化 / 加算法 / 加设计 / 加STAR / 加稳定性
```
并在每道"加码题"旁标 `[秋招加码]`，方便用户区分"录音实证"与"推演加码"。
